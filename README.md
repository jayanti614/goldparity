## What Phase 2 + 3 actually do

**Phase 2 (`app/analytics/fair_value.py`)** converts every contract's quoted
price into a purity-adjusted, per-gram, "999-equivalent" fair value — the
common basis every contract can finally be compared on.

**Phase 3 (`app/analytics/decomposition.py` + `detection.py`)**:
1. Estimates each contract's own implied daily carry rate from its own
   front-month vs next-month price (no external assumptions needed).
2. Roll-down-adjusts every contract to a common reference expiry day —
   if a contract has no next-month data to estimate carry from, it is
   deliberately left unadjusted rather than guessed (see
   `test_symbol_with_no_next_month_gets_no_roll_down_adjustment`).
3. Compares the adjusted prices to produce a `residual_signal_pct` per
   contract — what's left over after removing purity and roll-down effects.
4. `detection.py` flags a residual as statistically unusual only when it's
   an outlier against that *same contract's own* trailing 20-day history
   (z-score ≥ 2), computed look-ahead-safe so Phase 4's backtest can reuse
   these flags honestly.

Ran against your real uploaded file (18 Sep 2026): after normalization,
**GOLDTEN came out 0.115% cheap relative to the other three contracts** —
a real decomposed signal on real data, not synthetic noise.

## What Phase 4 + 5 actually do

**Phase 4 (`app/analytics/backtest.py`)** replays every flagged signal as a
hypothetical relative-value trade: enter the next trading day after a flag
(never the flag day itself — that would be lookahead), hold for a fixed
5-day period, measure the return as the change in residual over that
window, subtract realistic round-trip costs (4 leg-executions × a
configurable per-leg cost). Then it bootstrap-resamples the completed
trades' net returns to get a confidence interval on the average trade
return — and says plainly when that interval spans zero, meaning no edge
survives costs at the current sample size, rather than dressing up a small
noisy sample as a strategy.

**Phase 5a (`app/analytics/carry.py`)** fits a line through every available
(days-to-expiry, log price) point across all 4 contracts' curves that day
and reports the slope as a single implied annualized carry rate, along
with an R² so the number carries its own honesty check.

**Phase 5b (`app/analytics/delivery_risk.py`)** excludes any trade that
would still be open once its contract enters MCX's staggered-delivery
tender window — verified against real broker circulars (all 4 gold
contracts are compulsory-delivery; the tender window opens a few days
before expiry). This is a correction of an earlier, less accurate claim
made mid-project (originally described as "3 of 4 contracts, no fresh
positions on expiry day only" — the checked, real version is broader and
starts earlier than that).

**A bug the tests caught along the way:** the first version of Phase 3's
`reference_price` averaged all 4 contracts' prices *including the one
being evaluated*, which mechanically dampens and biases its own measured
deviation. Fixed to a leave-one-out reference (a contract's benchmark is
always the mean of the *other* contracts only) — standard relative-value
practice. This changed the backtest's headline result: before the fix, the
same 13 trades showed a statistically significant *negative* return; after
the fix, the honest result is "no significant edge at this sample size,"
which is what you'd expect from 13 trades where only one had a genuinely
engineered mispricing. Real historical MCX data across a much longer
window is what will actually answer whether there's a persistent edge —
this backtest engine is what will test it once that data is loaded.

## Repo layout

```
GoldParity/
  backend/
    app/
      contracts.py       # MCX gold contract reference data (real facts)
      db.py               # SQLite storage (SQLAlchemy) + query helpers
      analytics/
        fair_value.py      # Phase 2: purity + unit normalization
        decomposition.py   # Phase 3: roll-down adjustment + residual signal
        detection.py        # Phase 3: rolling z-score flagging
        backtest.py          # Phase 4: walk-forward backtest + bootstrap honesty check
        carry.py              # Phase 5a: implied carry rate (pooled OLS)
        delivery_risk.py       # Phase 5b: delivery-risk filter
        persistence.py          # ties analytics to the database
      pipeline/
        parser.py         # raw CSV -> clean typed rows
        fetcher.py         # gets raw CSV text (file mode works; live fetch is a TODO)
        loader.py         # upserts parsed rows into the database
      tests/
        test_parser.py
        test_fair_value.py
        test_decomposition.py
        test_detection.py
        test_backtest.py
        test_carry.py
        test_delivery_risk.py
        fixtures/
          real_mcx_sample_18092026.csv   # real MCX file, used as a test fixture
    scripts/
      generate_sample_data.py   # makes realistic test CSVs (front+next month, one injected mispricing)
      run_pipeline.py           # loads a directory of CSVs into the database
      run_analytics.py          # runs Phase 2+3 over everything in the database
      run_backtest.py            # runs Phase 4+5 over everything in the database
    sample_data/          # generated by generate_sample_data.py
    requirements.txt
  frontend/               # added in Phase 7
```

## Setup (Windows Command Prompt)

```
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

## Run it

```
python scripts\generate_sample_data.py
python scripts\run_pipeline.py
python scripts\run_analytics.py
python scripts\run_backtest.py
```

The last command prints the full trade log, the bootstrap confidence
interval and verdict, and the implied carry rate for every trade date.

## Run the tests

```
cd backend
python app\tests\test_parser.py
python app\tests\test_fair_value.py

python app\tests\test_detection.py
```

## Using a real MCX file

1. Download a CSV from https://www.mcxindia.com/market-data/bhavcopy by hand.
2. Put it in any folder.
3. `python scripts\run_pipeline.py --dir path\to\that\folder`

If the columns don't match what the parser expects, it will tell you exactly
which column it couldn't find — send that to Claude and we'll fix
`_HEADER_ALIASES` in `parser.py` to match.
